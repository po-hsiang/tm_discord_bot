虎喵小粉絲 Discord Bot

為遊戲實況主「老虎喵喵喵」粉絲社群打造的 Discord 互動機器人。以 discord.py 事件驅動為核心， 整合 OpenAI ChatGPT 人設對話、YouTube 歌單點歌、Google Sheets 餐點抽選、 抽籤與二選一淘汰賽小遊戲，並內建每日早安排程。

01系統架構圖

整體為單體式（monolithic）事件驅動架構：main.py 建立 Discord Client 並分派事件， 功能以 plugin 類別拆分；設定與金鑰統一由 json/config.json 提供。

架構重點：所有 plugin 於 啟動時一次性載入外部資料（YouTube 歌單、Google 試算表）， 執行期間不再刷新；AutoReplySystem 內部又自行 new 了一組 OpenaiAPI / YouTubeAPIHandler / EatWhatSystem，與 main.py 建立的實例並存， 造成外部 API 重複請求與狀態不同步（詳見問題清單 #6）。

02訊息處理流程圖（on_message）

每則訊息會依序通過「過濾 → 自動回覆路由 → 吃啥 → 點歌 → 查歌單」多段檢查； 各段為連續 if 而非互斥分支，同一則訊息理論上可觸發多個回覆。

03每日早安排程流程（RemindSystem）

Bot 上線（on_ready）時啟動一個 asyncio 常駐迴圈，每 60 秒醒來比對「時:分」， 命中 07:30 即透過 GPT 生成當日招呼語並附上隨機歌曲。

注意：GPT 呼叫為同步阻塞（含失敗重試 time.sleep(2)）， 在 asyncio 迴圈內執行時會凍結整個事件迴圈——早安生成期間 Bot 無法回應任何訊息， 極端情況甚至導致 Discord 心跳逾時斷線（問題清單 #2）。

07問題與優化建議

共 20 項，依「安全性 → 穩定性 → 正確性 → 品質」影響程度分為 高／中／低 三級。

🔴 高優先：安全性與穩定性

#位置問題建議
1youtube_handler.py:13 Google API Key 明碼寫死在原始碼。此檔尚未 commit，一旦入版控即永久留在歷史紀錄。 改由 config.json 讀取；該金鑰視同已外洩，建議至 GCP 撤銷重發，並加上 API 限制。
2openai_api.py＋main.py／remind_system.py OpenAI 為同步呼叫（含 time.sleep(2) 重試），在 async 事件處理器內執行會凍結整個事件迴圈：GPT 回覆期間 Bot 無法處理任何訊息，可能造成 Discord 心跳逾時斷線。 改用 asyncio.to_thread() 包裝，或升級 openai ≥1.0 使用 AsyncOpenAI；重試等待改 asyncio.sleep。
3main.py／eat_what_system.py／youtube_api.py 啟動時同步抓取 Google 試算表與整個 YouTube 歌單，任一外部服務故障就整隻 Bot 起不來；且 restart: always 會無限重啟、狂打 API。 延遲載入（lazy load）＋失敗降級（該功能回覆「暫時無法使用」），啟動流程加上重試與退避。
4scripts/config_utils.py 開檔未指定 encoding="utf-8"（Windows 預設 cp950 可能解析失敗）；讀檔失敗回傳 None，後續 CONFIG.get() 直接 AttributeError，錯誤訊息失焦。 統一加 encoding；設定檔缺失時直接 raise SystemExit 並印出明確原因（fail-fast）。
5remind_system.py:35-38, 48-51 get_channel() 若回傳 None（ID 錯誤或快取未就緒），背景任務拋出例外後靜默死亡——早安功能從此消失且無任何紀錄。 迴圈內加 try/except＋log；或改用 discord.ext.tasks.loop，內建例外處理與重啟。

🟠 中優先：正確性與架構

#位置問題建議
6main.py:15-18＋auto_reply_system.py:10-13 重複實例化：OpenaiAPI / YouTubeAPIHandler / EatWhatSystem 在 main 與 AutoReplySystem 各建一份 → 歌單抓兩次（API 配額×2、啟動變慢）、兩份 GPT 對話歷史互不同步（!問 與早安用的不是同一份）。 改為依賴注入：main 建立單一實例傳入 AutoReplySystem。
7remind_system.py:29-53 每 60 秒輪詢比對「時:分」，可能同一分鐘觸發兩次（重複發早安）或跨分鐘漏發（迴圈耗時漂移時）。 計算「距下次 07:30 的秒數」一次 sleep 到位；或改用 discord.ext.tasks／APScheduler 的 cron 觸發。
8two_choices_one_system.py 遊戲狀態為全頻道共享單例：多人同時玩會互相干擾；遊戲進行中任何人打「左/A/右/B」都算選擇。 以 channel_id（或發起者 user_id）為 key 管理各自的遊戲狀態。
9eat_what_system.py／youtube_api.py 資料只在啟動時載入——試算表新增餐點、歌單加歌都要重啟 Bot 才生效。 加上 !reload 管理指令或定時（如每日）背景刷新。
10pyproject.toml 技術債三連：Python 3.8 已於 2024-10 EOL；openai 0.27 為已淘汰的舊版 SDK；google-api-python-client、requests 為隱式相依（靠 pygsheets 間接帶入，未宣告）。 升級 Python ≥3.11、openai ≥1.x（需改寫呼叫），並將實際 import 的套件明確列入相依。
11main.py:65-66 !查歌單 以 user_msg[5:] 取關鍵字——若使用者沒加空格（如 !查歌單周杰倫），關鍵字第一個字會被吃掉。 改用 split(" ", 1) 或 user_msg[4:].strip()。
12openai_api.py:82-96 !搜圖 依賴的 source.unsplash.com 隨機圖服務已停止營運，此功能實際上已壞。 改接 Unsplash 官方 API（需金鑰）或其他圖片來源，或先下架此指令。
13scripts/config_utils.py vs utils/config_utils.py 兩份幾乎相同的設定讀取工具，行為卻不一致（encoding、路徑解析），日後易改一漏一。 合併為單一模組，由兩邊共同 import。
14main.py:54 user_msg.replace("!", "") 會移除訊息中所有驚嘆號，非只去除開頭前綴。 改用 user_msg[1:] 或 removeprefix("!")。
